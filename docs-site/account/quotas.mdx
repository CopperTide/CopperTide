## Hosted orgs

Hosted Shakedown runs each run in a cloud sandbox of its own. Every org starts on the beta plan.

| Limit | Hosted today |
|---|---|
| Runs at once | One per org. A run started meanwhile waits as **Queued for a cloud slot** and starts by itself, first come first served. |
| Runs waiting | 50 per org. Beyond that, starting a run answers 429. |
| Longest run | 55 minutes. A run still going then ends `stopped`. |
| Saves kept | 20 GiB |

The beta plan also lists 2 sandboxes at once and 180,000 sandbox seconds (50 hours) a month. Shakedown does not count these yet. Model spend on your org's own keys has no limit here: set a spend limit per run instead.

Hosted Shakedown refuses, for now:

- Forking a cloud run.
- Installing, checking or removing a runtime, and Import from git.
- Deploying a world that starts from uploaded data files.

## Every engine

| Limit | Value |
|---|---|
| Setups per engine experiment | 1 to 50 |
| Runs per setup | Up to 1000 (5 by default) |
| A run's spend limit | `max_cost_usd`, `budget.per_run_usd`, or `SHAKEDOWN_MAX_COST_USD`. None by default. |
| A Code connection's run | `SHAKEDOWN_CODE_RUN_SECS`, 900 seconds by default |
| An HTTP agent's turn | 15 minutes |
| A dispatch run | 60 minutes by default (`SHAKEDOWN_DISPATCH_MAX_MINUTES`) |
| Saves on a local engine | `SHAKEDOWN_MAX_DB_BYTES`, 5 GiB by default |
| A request body | 2 MiB on an engine serving others |

At the saves limit, new runs and forks answer 507 until you delete old runs. Deleting a run drops its saves, stops its live instances and removes its events.
