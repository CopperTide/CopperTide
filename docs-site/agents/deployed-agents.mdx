title: Bring a deployed agent
description: Test an agent already running behind a URL, or a model on Amazon Bedrock, as one member of a team.
---

Your agent stays where the agent runs. Shakedown sends the agent the task and an MCP endpoint with the world's tools, records every tool call, and scores the world with the task's checks. Two kinds of team member do this.

| Kind | Team member | What runs the agent |
|---|---|---|
| `http` | `{kind: "http", url, headers?, auth?}` | Your service, behind a URL |
| `bedrock` | `{kind: "bedrock", model_id, region}` | Shakedown's own tool-use loop on Bedrock's Converse API |

## Connect your agent

1. Click **Connect an agent** at the bottom of the sidebar, or **Connect your agent** in the team picker of Run once or New experiment.
2. Under **Where your agent runs**, pick **HTTP** or **Bedrock**.
3. For HTTP, enter the URL and any headers, one `Name: value` per line. For Bedrock, name the model and the region.
4. Click **Test connection**, then **Use this agent**. On the test, for HTTP, Shakedown sends a `shakedown-agent/1` hello and shows the name your agent answers with. For Bedrock, Shakedown makes one Converse call of one output token.

Instead of typing a credential as a header, name one of your own stored keys: `auth: {key: <name>}` (on a local engine also `{env: SHAKEDOWN_AGENT_NAME}`). Shakedown reads it again from your key on each request and sends it as `Authorization: Bearer <secret>`. Only `http` agents take `auth`; any other kind is refused with a 400.

Header values never reach a log, an API answer or a saved run, and only the caller who typed them can use them again. On a local engine, the person in the app, each API token and each MCP client count as different callers: a header typed in the app cannot be cited by your API token or an MCP client, and the other way round. Type it again, or use `auth`. Put credentials in headers, not in the URL: Shakedown stores the URL with the team.

## The HTTP protocol

When the agent's turn starts, Shakedown sends one `POST` to the URL, with your headers:

```json
{
  "protocol": "shakedown-agent/1",
  "type": "run",
  "run_id": "0abe2f29…",
  "branch_id": "20ba9b19…",
  "agent": "planner",
  "task": "<the agent's prompt, the ticket, the instructions and any handoff notes>",
  "mcp_url": "http://127.0.0.1:4510/mcp/<branch>/<agent>",
  "gateway_url": "http://127.0.0.1:4510/gateway/<branch>/<agent>/v1",
  "token": "<the agent's token, sda_…>",
  "deadline": "2026-11-09T04:18:33Z"
}
```

Your agent works through `mcp_url`, sending `Authorization: Bearer <token>` on every call. The same token opens `gateway_url`, an OpenAI-compatible gateway, so the agent's model calls get recorded too. Your agent answers the `POST` when done:

| Your agent answers | The run |
|---|---|
| Any 2xx, optionally `{"ok": true, "usage": {...}, "cost_usd": x}` | Scored by the checks |
| `{"ok": false, "error": "…"}` | `failed` |
| No answer by the deadline (15 minutes) | `failed` |
| An error status, or no connection | `infra_error` |

The request stays open while the agent works, so a gateway in front of your agent with a shorter timeout needs a direct URL. AWS API Gateway, for example, cuts at 29 seconds.

`sdk/python/examples/agent_server.py` is a complete HTTP agent in about 70 lines. Run the example with `uv run python examples/agent_server.py 8765` from `sdk/python`, then connect `http://127.0.0.1:8765`.

## Where your agent runs

A local engine listens on 127.0.0.1 only. An agent on another machine reaches `mcp_url` through a tunnel you run: set `SHAKEDOWN_PUBLIC_URL` to the tunnel's base URL. Through the tunnel only `/mcp` and `/gateway` answer, each with the run's token.

In hosted Shakedown an agent's URL must be HTTPS on a public address. Shakedown refuses private and metadata addresses on save, on test and on every call.

## Bedrock

Shakedown signs each call with your AWS credentials: `AWS_BEARER_TOKEN_BEDROCK`, else `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, else what the AWS CLI resolves. A Bedrock key added in **Connections & models** serves its region. Bedrock costs show as unknown.

## What has run live

The HTTP example ran one live run on 2026-11-08, with Claude Code (`haiku`) behind the URL, on the Factory-01 task `supplier-delay`. The run passed every check in 24 seconds. One run, an observation. No Bedrock call has run live yet: the request signing passes AWS's own test vector, and the translation runs against a local server standing in for Bedrock.
