title: Experiments
description: Run one scenario against the setups you compare, and read pass rates, checks, safety, cost and time.
---

An experiment runs every setup against one scenario, as many times as you ask, and shows the setups side by side. One run of an LLM agent says little, so read rates, not single runs.

## Create and deploy

1. Open **Experiments** and click **New experiment**.
2. Name the experiment, pick the world, a scenario in the world, and the setups to compare. Set **Runs per setup**.
3. Click **Create experiment**. Nothing runs yet.
4. Click **Deploy** on the experiment's page. The dialog says how many runs you start: setups times runs per setup. Every run calls a real model. Deploy refuses a setup whose `key` or `auth` names a key that is not stored or not yours to use, and an `auth.env` variable that may not be sent (hosted: any; local: names not starting with `SHAKEDOWN_AGENT_`).

The experiment's page leads with its runs. Under **Runs**, each deployment shows each setup's passes. Click **Open results** for the full page. The experiment's settings sit below, folded under **Configuration**: closed, one line such as "3 setups × 5 runs = 15 runs · paired seeds · $1.50 cap a run"; open, the editor for its world, scenario, setups, runs per setup and spend cap. On a local engine, **Experiment on a benchmark…** in the **⋯** menu starts an engine experiment straight from a benchmark, with no files.

```yaml
format: shakedown-experiment/1
label: "Supplier slip: solo vs team"
world: larkspur-plant
scenario: supplier-slip
setups: [solo-planner, planning-team, planner-with-rules]
repeats: {per_setup: 5, paired_seeds: true}
budget: {per_run_usd: 1.5, per_deployment_usd: 20}
parent: supplier-slip-baseline   # optional: the experiment this one branched from
```

| Field | What the field holds |
|---|---|
| `world`, `scenario` | The scenario must happen in this world |
| `setups` | One or more setup ids |
| `repeats.per_setup` | Runs per setup, at least 1 |
| `repeats.paired_seeds` | Run *n* of every setup uses the same seed. Seeds stay paired today whatever this says. |
| `budget.per_run_usd` | Each run's spend limit |
| `budget.per_deployment_usd` | A cap for one deployment. Deploys do not read this field yet. |
| `parent` | The experiment this one branched from, shown as a sub-experiment in the list |

## Find and delete an experiment

**Experiments** lists every experiment, sub-experiments under their parent. Each row says whether the experiment ran:

| Status | Meaning |
|---|---|
| **Running** | A deployment is running now |
| **Has results** | At least one run has ended |
| **Ran, no results** | It was deployed, and no run has ended |
| **Not run yet** | It was never deployed |

Hover a status for the runs ended and the last deployment. **Any status** narrows the list to one status. The sort is **Grouped**, parents with their sub-experiments, **Has results first** or **Last deployed**. A scenario's page also lists the experiments playing the scenario: see [Scenarios and disruptions](/runs/scenarios).

An experiment's page shows the path to the experiment under its name: the world, then the scenario, each a link to its page. **Worlds** also lists every experiment under its scenario.

**Delete** on the experiment's page, or the bin on the experiment's row in **Experiments**, deletes the experiment's file. Sub-experiments of the experiment become experiments of their own. Past runs of the experiment stay, listed under **Earlier experiments** on the same page. Click **Undo** in the message after the delete, or **Undo last delete** in **Project settings → Deleted files**, to bring the file back with its runs.

## How the runs go

Shakedown makes the runs one at a time, interleaved: the first run of every setup, then the second of every setup, and so on. Run *n* of every setup starts the world from the same seed. Every run starts from the same base world, so what varies is the agents. An engine experiment takes 1 to 50 setups and up to 1000 runs per setup, as safety caps.

To stop, click **Stop** on the results page. The run in progress stops, no more runs start, and ended runs stay scored.

## Read the results

Each setup gets a column:

- **Pass rate**: the share of scored runs passing every check, safety included, with the 95% range under the bar.
- **A square per run**: click one to open the run.
- **Checks**: each check's pass rate, with safety checks tagged.
- **Safety**: failed safety checks, refused actions and flags for a human.
- **Cost and time** per run, with the estimate of time in production (measured time minus Shakedown's own overhead).

Only scored runs count in the rates. A run ending without a score (an infrastructure error, a stop) counts as unscored.

Under the setups' columns, **Configuration** is folded: the benchmark, runs per setup, the seed, the world time window, the spend cap per run, when the experiment started and ended, and each setup's runner and agents with their models.

<Note>
Hosted Shakedown runs each run in a cloud sandbox of its own, one at a time per org. A run started while another is going waits as **Queued for a cloud slot** and starts by itself, first come first served. A cloud run lasts at most 55 minutes. See [Quotas and limits](/account/quotas).
</Note>
