You build four files in this guide: a world, a scenario, an agent setup and an experiment. The example uses the retail benchmark, a customer-service task on one Postgres database, from tau2-bench retail.

<Note>
Hosted Shakedown builds and edits these files today. Pressing Run in the cloud arrives with the sandbox runner, which is in progress. To run the experiment now, start the open-source engine on your computer ([Self-host](/self-host)) and follow the same steps there.
</Note>

<Steps>
  <Step title="Sign in">
    Open [app.coppertide.ai](https://app.coppertide.ai/) and sign in with Google or GitHub. You land in Shakedown at `/sd/`, in your personal org. The account menu at the top right shows your orgs and **Sign out**.

    On a local engine there is no sign-in. Open the UI at the address from [Self-host](/self-host).
  </Step>
  <Step title="Open Get started">
    Click **Get started** at the bottom of the sidebar. The first step shows your project. On a local engine with no project yet, give the project a name and click **Create project**. A project is a folder of YAML files, one per world, scenario, setup and experiment.
  </Step>
  <Step title="Connect a model">
    Open **Connections & models** in the sidebar and add a key under **Add a key or server**. Every run calls a real model. On a local engine, Claude Code and Codex use your own CLI sign-in instead. See [Models and providers](/agents/models).
  </Step>
  <Step title="Make a world">
    Open **Worlds** and click **New world**. Name the world `Retail store`. Open its **Runtime** section and pick `retail` as the runtime package, then click **Save**.

    Today a world runs through an installed benchmark or a built world, named as its runtime package. Worlds that run from their files alone are planned. Hosted Shakedown has no runtime packages installed yet, so its list shows **None yet**. See [Runtime package](/worlds/runtime).
  </Step>
  <Step title="Write a scenario">
    Open **Scenarios** and click **New scenario**. In **Inputs**, pick the world, enter `27` as the task of the world's runtime, and write the ticket. Save.
  </Step>
  <Step title="Describe an agent setup">
    Open **Agent setups** and click **New agent setup**. Under **How it runs**, pick **Claude Code**. Save.
  </Step>
  <Step title="Create the experiment">
    Open **Experiments** and click **New experiment**. Name the experiment, pick the world, the scenario and the setup, and set **Runs per setup** to 3. Click **Create experiment**.
  </Step>
  <Step title="Deploy">
    On the experiment's page, click **Deploy** and confirm. The **Runs** tab lists each deployment. Click **Open results** to see the pass rate, every run and its checks. See [Experiments](/runs/experiments).
  </Step>
</Steps>

## The files you made

The editors write these files into the project folder. You edit them in the app, through the [MCP server](/code/mcp), or with any text editor on a local engine.

```yaml
# worlds/retail-store/world.yaml
format: shakedown-world/3
label: Retail store
package: retail
```

```yaml
# scenarios/return-and-exchange.yaml
format: shakedown-scenario/1
label: Return and exchange
world: retail-store
preset: "27"
task: The customer wants to return two items and exchange the boots.
```

```yaml
# setups/claude-code.yaml
format: shakedown-setup/1
label: Claude Code
team:
  kind: claude-code
```

```yaml
# experiments/first-try.yaml
format: shakedown-experiment/1
label: First try
world: retail-store
scenario: return-and-exchange
setups: [claude-code]
repeats: {per_setup: 3}
```

Today each run gets the ticket of the preset task from the runtime package. The ticket you write in `task` stays in the file for readers. See [Scenarios and disruptions](/runs/scenarios).
