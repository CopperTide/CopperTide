---
title: Quickstart
description: Sign in, set up a project and a model, add the ready example and deploy its first run.
---

You set up a project and a model, add a small, real example with one click, and deploy it. The example is an order desk on the retail benchmark: one agent works a customer ticket against a fresh copy of a store's Postgres database, from tau2-bench retail. The run passes only if the database ends exactly as it should. No model judges it.

<Note>
The steps are the same in hosted Shakedown and on the open-source engine on your computer ([Self-host](/self-host)). Hosted Shakedown runs each run in a cloud sandbox of its own.
</Note>

<Steps>
  <Step title="Sign in">
    Open [app.coppertide.ai](https://app.coppertide.ai/) and sign in with Google or GitHub. You land in Shakedown at `/sd/`, in your personal org. The account menu at the top right shows your orgs and **Sign out**.

    On a local engine there is no sign-in. Open the UI at the address from [Self-host](/self-host).
  </Step>
  <Step title="Create your project">
    Shakedown opens on **Get started** until setup is done. Setup has two steps, both on this page: **Your project** and **Connect a model**. There is no skipping: until both are done, every page sends you back here.

    Under **Your project**, give the project a name and click **Create project**. On a local engine the project is a folder of YAML files, and **Track with git** commits them like code. Hosted projects live in a database, so hosted Shakedown does not offer git.
  </Step>
  <Step title="Connect a model">
    Get started moves on to **Connect a model** by itself. Every run calls a real model, so add a provider key here:

    1. Under **Add a key**, keep **OpenRouter**, or pick another kind.
    2. The key's **Name** starts as the kind. Type your own if you like. The field turns what you type into lowercase letters, digits, `-` and `_`, so `OpenRouter Key` becomes `openrouter-key`.
    3. Paste the key and click **Save**.

    Once both steps are done, Shakedown opens. On a local engine, a key set as an environment variable before you start the engine also counts. See [Models and providers](/agents/models).
  </Step>
  <Step title="Add the example">
    While your project has no worlds, **Home** shows **Start from an example**. Click **Add the example**. Shakedown adds four items to your project:

    - **Order desk (example)**, a world on the built-in `retail` runtime, in the group **Examples**.
    - **Bookshelf swap, or cancel the order**, a scenario with one customer ticket.
    - **Order desk agent**, a one-agent setup on the model key you connected.
    - **Order desk: first run**, an experiment with one run, capped at $0.50.

    Nothing is added before you click. Shakedown then opens the experiment.
  </Step>
  <Step title="Deploy">
    On the experiment's page, click **Deploy** and confirm. A run takes about a minute. In hosted Shakedown, a run waits as **Queued for a cloud slot** while another run of your org is going. Under **Runs**, the deployment shows the setup's passes. Click **Open results** to see the pass rate, the run and its checks. See [Experiments](/runs/experiments).
  </Step>
  <Step title="Read the run">
    On the results page, click the run's square. The run page shows every step: each model call, each tool call with what it read and wrote, and the check at the end. See [Watching a run](/runs/watching).
  </Step>
</Steps>

## The files the example adds

The example is ordinary project items. Edit or delete any of them afterwards. On a local engine they are files in the project folder.

```yaml
# worlds/order-desk/world.yaml
format: shakedown-world/3
label: Order desk (example)
group: Examples
package: retail
connectors:
- id: retail
  label: The store's customers, orders and products (a Postgres copy, restored for every run)
  mode: stand-in
```

```yaml
# scenarios/order-desk-ticket.yaml
format: shakedown-scenario/1
label: Bookshelf swap, or cancel the order
world: order-desk
task: >-
  Daiki Silva (daiki.silva6295@example.com) wants the bookshelf in a pending order changed to the
  4-foot one in the same material and colour. ...
preset: '88'
```

```yaml
# setups/order-desk-agent.yaml (key and model come from the key you connected)
format: shakedown-setup/1
label: Order desk agent
team:
  kind: builtin
  agents:
  - id: agent
    key: openrouter
    model: deepseek/deepseek-chat-v3.1
    max_tokens: 4000
    tools: ['*']
    role: You are the order desk agent of an online store. ...
```

```yaml
# experiments/order-desk-first-run.yaml
format: shakedown-experiment/1
label: 'Order desk: first run'
world: order-desk
scenario: order-desk-ticket
setups: [order-desk-agent]
repeats: {per_setup: 1, paired_seeds: true}
budget: {per_run_usd: 0.5}
```

The agent runs on your newest key that has not failed its test, and on the model that key names. A key without a model gets the example's model for its kind: `deepseek/deepseek-chat-v3.1` on OpenRouter, `claude-haiku-5-5` on Anthropic, `gpt-4.1-mini` on OpenAI. For a key of kind **Your server** or **Bedrock**, give the key a model first.

The card shows only while the project has no worlds. Adding the example again is refused when any of its ids is taken, and nothing is overwritten. The same is the `project.example` operation for the [MCP server](/code/mcp) and the [HTTP API](/code/http-api).
