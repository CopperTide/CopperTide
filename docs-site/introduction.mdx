Shakedown tests agent systems before production. You build a **world**, a working copy of the systems your agents touch: databases, an ERP, a CRM, a ticket tracker, plant controls. You write a **scenario**, a task in the world with the disruptions you want to throw at the agents. You describe each **agent setup** you want to compare. An **experiment** runs every setup against the scenario as many times as you ask and shows the results side by side.

Shakedown records every tool call and model call and saves the world after every step. You open any run, read each step, rewind to a step and fork the run with one thing changed.

## Two ways to use Shakedown

| | Hosted Shakedown | The open-source engine |
|---|---|---|
| Where | [app.coppertide.ai/sd](https://app.coppertide.ai/sd/) | Your own computer, see [Self-host](/self-host) |
| Account | Google, GitHub or an invited password account | None |
| Projects | Your org's projects, kept in a database and edited in the app | A folder on your disk |
| Runs | Each in a cloud sandbox of its own | On your computer |

<Note>
Hosted Shakedown runs each run in a cloud sandbox of its own. Forking a cloud run, installing runtimes, Import from git and deploying a world that starts from uploaded data work only on a local engine for now. See [Self-host](/self-host) and [Quotas and limits](/account/quotas).
</Note>

## What Shakedown measures

- **Pass rate per setup**, with a 95% range, over the runs of an experiment.
- **Checks** each run passed, with safety checks counted apart from goals.
- **Refused actions and flags for a human**, step by step.
- **Time, tokens and cost** per run and per agent.

Scoring uses deterministic checks on the final state of the world, never a model. An optional AI review explains a run and cites its steps. The review never changes a score.
