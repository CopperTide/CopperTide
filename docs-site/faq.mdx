title: FAQ

---

<AccordionGroup>
  <Accordion title="Do runs work in hosted Shakedown?">
    Yes. Each run gets a cloud sandbox of its own, one at a time per org, and runs started meanwhile wait their turn. A cloud run lasts at most 55 minutes. Forking a cloud run, installing runtimes, Import from git and deploying a world that starts from uploaded data work only on a local engine for now: see [Self-host](/self-host) and [Quotas and limits](/account/quotas).
  </Accordion>
  <Accordion title="Why does my world need a runtime package?">
    Worlds need a runtime package today: an installed benchmark or a built world supplies the parts, tools, data, tasks and checks. CopperTide plans worlds running from their files alone. See [Runtime package](/worlds/runtime).
  </Accordion>
  <Accordion title="Does Shakedown import my system from GitHub?">
    On a local engine, yes: **Import from git** on the **Worlds** page imports a repository holding Shakedown packages and project files. You can also install one runtime package from a git URL or an archive in **Settings → Advanced → Runtimes**. Hosted Shakedown refuses both for now. A system without packages comes in as a Docker Compose project through the `service` integration. See [Bring your own systems](/worlds/your-systems).
  </Accordion>
  <Accordion title="What is the quickest way to see a run?">
    Finish **Get started**, then click **Add the example** on **Home** and **Deploy** on the experiment it opens. See the [Quickstart](/quickstart).
  </Accordion>
  <Accordion title="Where did the Analytics page go?">
    The app no longer has an Analytics page, Search or Explore. Read results on each experiment's page. The figures across runs, the step search and Explore stay as the `analytics.*` and `explore.*` operations, for the [MCP server](/code/mcp), the assistant and the [HTTP API](/code/http-api).
  </Accordion>
  <Accordion title="Does Shakedown use a model to score runs?">
    No. Deterministic checks on the final state of the world decide pass or fail. The optional AI review explains a run and never changes a score.
  </Accordion>
  <Accordion title="Does Shakedown ship scripted or fake agents?">
    No. Every agent in a run is a real model: Claude Code, Codex, an API model, or your own code calling a model.
  </Accordion>
  <Accordion title="Which agents has Shakedown measured live?">
    Claude Code and Codex. CopperTide built API-model agents, OpenRouter, self-hosted model servers, Bedrock, HTTP agents and the framework adapters, and tests them against simulated servers, with live checks in progress. See [Models and providers](/agents/models).
  </Accordion>
  <Accordion title="Why did my fork start earlier than the step I picked?">
    A Claude Code or Codex session cannot resume mid-way, so a fork during a CLI agent's turn starts at the start of the agent's turn. The run page says where the fork started and why. See [Rewind and fork](/runs/rewind-and-fork).
  </Accordion>
  <Accordion title="Why did Shakedown refuse my fork?">
    A part of the world cannot restore in the mode you asked for, and the refusal names the part. Try **Approximate**, or check the part's restore in [Concepts](/concepts).
  </Accordion>
  <Accordion title="Where do my keys go?">
    Shakedown seals each key and shows only its last four characters. Built-in, Claude Code and Codex agents never hold a key: model calls go through Shakedown's gateway. A key you name in an HTTP setup's `auth` is sent to that endpoint on each request. See [Model keys and security](/account/keys-and-security).
  </Accordion>
  <Accordion title="Where is the old team-of-agents documentation?">
    The team-of-agents product is hidden, and its pages left this site's navigation. Their sources stay in the CopperTide repository.
  </Accordion>
</AccordionGroup>
